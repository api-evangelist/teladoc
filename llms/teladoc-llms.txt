# Teladoc Health

> Teladoc Health is a global virtual-care company (telehealth, behavioral health, chronic-condition management and expert medical opinion). Its developer surface is the Solo platform: a partner-gated REST API (the Solo External API, served under /qapi/v1 on visitnow.org) plus native iOS/Android Mobile SDKs for embedding virtual care into partner apps. Access is granted under a partner agreement and Business Associate Agreement (BAA); authentication is a static Api-Key header. Generated by the API Evangelist enrichment pipeline, 2026-08-15.

## APIs
- [Solo External API](https://intouchhealth.github.io/solo-slate/): REST API for patients, appointments, waiting rooms, visit notes, appointment slots, attachments, patient documents, episodes of care, encounter reports, Perfect Answer, virtual nursing/sitting (request-assistance), and webhooks. 44 documented operations under /qapi/v1. Base host: demo.visitnow.org (the only host published; production is tenant-specific). Auth: Api-Key header.

## Docs
- [Solo External API Reference](https://intouchhealth.github.io/solo-slate/): the full operation reference (Slate). HTTP 200.
- [Developer Hub](https://api-documentation.teladochealth.com/): Teladoc Health developer documentation portal — currently returning Cloudflare "error code: 1014", i.e. unreachable.

## Events
- [Webhooks](asyncapi/teladoc-webhooks.yml): 13 event types across patient, appointment, episode and intake lifecycles. Payloads AES-256-CBC encrypted with a per-subscription key. Register at POST /qapi/v1/webhooks. `intake:completed` delivers a FHIR-shaped DiagnosticReport with contained Observation resources.

## Notes for agents
- There is no published OpenAPI, AsyncAPI, GraphQL schema, agent card or MCP server for this provider. The operation list above was read from the human documentation.
- The API is not self-serve: no key can be obtained without a partner agreement and a BAA. Do not attempt to call it on a user's behalf without provisioned credentials.
- PHI is in scope on every endpoint. Treat all payloads as protected health information.
